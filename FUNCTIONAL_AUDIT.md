# BulkBuy Marketplace — Complete Functional Audit

**Audit Date**: October 2026  
**Auditor**: Senior Full-Stack, QA & Security Engineer  
**Scope**: Full end-to-end audit of BulkBuy Group-Commerce Marketplace across architecture, frontend, backend REST API, business logic, security, and persistent storage.

---

## Executive Summary

BulkBuy is a group-commerce marketplace enabling apartment communities in Indian urban hubs (Bengaluru, NCR, Mumbai, Pune, Hyderabad) to aggregate demand for daily staples (cold-pressed oils, stone-ground flours, pulses, rice) directly from certified agricultural mills. 

While the core presentation, pricing algorithm, and authentication security hardening (bcrypt, JWT HS256, rate limiting, and RBAC) are functional, an exhaustive inspection reveals critical functional defects, disconnected forms, missing endpoints, insecure payment simulation bypasses, broken address management, and lack of URL routing synchronization.

## Remediation Roadmap

The repair workflow will execute systematically across the following phases:

1. **Phase 1: Authentication & User Accounts (Module A)**
   - Add profile update endpoint (`PUT /auth/profile`) and frontend profile editing.
   - Fix address creation form in `AccountPage.tsx` (`api.addAddress`).
   - Add address editing (`PUT /auth/addresses/:id`), deletion (`DELETE /auth/addresses/:id`), and default address selection (`PUT /auth/addresses/:id/default`).
   - Fix session persistence to respect explicit user logout.
   - Write comprehensive automated tests for all Module A operations.

2. **Phase 2: Payments & Order Integrity (Modules D, E)**
   - Eliminate insecure mock signature bypasses (`startsWith('sig_mock_')`).
   - Persist authoritative pending order drafts on the server in `db.ts`.
   - Prevent duplicate order creation and duplicate payment replay attacks.
   - Fix admin CSV report download via query token support and frontend blob download.
   - Add tests for payment verification, tampering rejection, and idempotency.

3. **Phase 3: Group-Buy Engine & Concurrency (Modules C, F)**
   - Enforce strict server-side reservation ownership and TTL in `createOrder`.
   - Implement automatic campaign lifecycle transitions for expired deadlines.
   - Add dynamic tier slab progression calculation in campaign detail page.
   - Add tests for concurrency, reservation TTL expiry, and quota capping.

4. **Phase 4: Supplier & Administrator Workflows (Modules G, H)**
   - Implement supplier product editing and deletion with ownership checks.
   - Implement full administrative order search and inspection view (`GET /admin/orders`).
   - Add tests for supplier catalog management and admin order oversight.

5. **Phase 5: Location, Delivery & Navigation (Modules B, I, K)**
   - Add regional campaign filtering by location hub.
   - Validate delivery address eligibility against campaign region in `createOrder`.
   - Implement hash-based URL routing in `App.tsx` for browser back/forward and refresh persistence.
   - Full regression and end-to-end testing across all user personas.
